# EWAO × UDD — Estrategia de Internacionalización y Marketing Global

> **Pregunta central del semestre:** Si este equipo tuviera un semestre para ayudar a internacionalizar EWAO, ¿qué construiría exactamente?

## ¿Qué es EWAO?

EWAO es un modelo de trabajo que conecta directamente comunidades indígenas con profesionales, empresas, universidades y especialistas de diferentes sectores para diseñar y desarrollar soluciones conjuntamente.

Actualmente el modelo se desarrolla junto a la **Asociación Keweriono**, en territorio Waorani de la Amazonía ecuatoriana. A través del trabajo directo se han identificado y desarrollado **22 iniciativas** vinculadas a conservación, biodiversidad, salud, educación, energía, conectividad, movilidad, turismo, bioeconomía, producción, infraestructura y cultura.

## El reto

Convertir este ecosistema en una estructura capaz de **comunicar, comercializar, internacionalizar, captar recursos y gestionar oportunidades profesionalmente** — automatizando al máximo la captación y gestión de contactos.

## Principios EWAO

1. **Desde el territorio hacia el mundo** — Las comunidades no son beneficiarias pasivas: participan en las decisiones.
2. **Colaboración, no asistencia** — EWAO conecta conocimiento comunitario con capacidades profesionales externas.
3. **Internacionalización sin pérdida de identidad** — Crecer no significa convertir la cultura Waorani en un producto genérico.
4. **Comunicar solo lo demostrable** — Diferenciar claramente entre realizado, en desarrollo y proyectado.
5. **Automatizar antes de aumentar estructura** — La tecnología debe permitir crecer sin multiplicar innecesariamente la gestión manual.
6. **Resultados utilizables** — El valor académico debe traducirse en capacidad real para EWAO.

## Cómo colaboramos

Cada grupo trabaja en su propia branch y abre Pull Requests hacia `develop`. Revisa [`CONTRIBUTING.md`](./CONTRIBUTING.md) para el flujo completo de branches, PRs e issues.

## Para estudiantes: primeros pasos

1. Clona este repositorio
2. Lee el [`docs/brief.md`](./docs/brief.md) completo
3. Revisa tu carpeta en `areas/` y su README
4. Crea tu branch: `git checkout -b grupo/XX-nombre-feature`
5. Trabaja en tu área siguiendo los capítulos de la entrega
6. Abre PR cuando tengas avance para revisión
